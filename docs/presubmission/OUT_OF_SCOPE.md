- `scripts/make_anon_bundle.py:509` (the self-test's planted commit) against `:177` (`commit_sweep_pattern`'s float guard). Found in S10-fix.
  - **What happens.** The self-test plants the newest commit's 7-character prefix. The detector deliberately refuses a run of digits with one `e`, so that a float such as `5e30429` is never taken for a commit.
  - **When it bites.** When HEAD's prefix has that shape, the self-test fails its own assertion ("a planted commit hash was not detected") and the anonymised bundle is not built. That is about one commit in forty. It happened at local commit 5e30429, which was never pushed or bundled.
  - **The consequence.** In a clean clone whose HEAD has such a prefix, stage 28b would fail.
  - **This session's workaround.** It changed the input: it built the bundles on a HEAD with an ordinary prefix, and checked that the pushed HEAD has one too.
  - **A fix, which is the user's call.** Plant the commit's full 40-character hash, which the detector does match. That is a stronger probe, not a looser check.
